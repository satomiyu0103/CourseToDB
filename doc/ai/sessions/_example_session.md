# セッション記録: 認証方式の選定（見本・架空）

## 背景・課題

- 利用者が複数端末からアクセスする想定
- MVP ではセルフホスト前提。マネージド IdP のコストは抑えたい
- 既存の社内アカウント基盤との連携要否が未確定

## 意思決定

| 項目 | 採用 | 非採用 |
|---|---|---|
| 認証方式 | セッション + メールリンク（MVP） | OAuth ソーシャルログインのみ |
| トークン保存 | HttpOnly Cookie | localStorage |
| 将来拡張 | OIDC 連携を Phase 2 で検討 | 初版から Keycloak 必須 |

## 実装サマリ

- ログイン・ログアウトのエンドポイントを追加
- セッション有効期限を 24 時間に設定
- 未認証アクセスは 401 で統一

## 学び

- MVP では OAuth よりメールリンクの方が実装コストと運用負荷のバランスが良い
- トークンは HttpOnly Cookie に統一すると XSS 耐性と実装の単純さを両立できる
- 昇格候補: なし（Phase 2 で OIDC 検討時に ADR 化を検討）
